# Этап 09. Саммари и экспорт сохранённого митинга

## Цель

Добавь явное пользовательское действие для создания саммари уже завершённого локального transcript. Саммари не является режимом и никогда не запускается автоматически при записи.

## Поток

1. Пользователь открывает завершённый meeting и нажимает `Создать саммари`.
2. Приложение формирует упорядоченный transcript с source и таймкодами.
3. Перед отправкой показывает объём и предупреждает, что текст будет передан внешнему API.
4. По подтверждению отправляет только текст, без аудио.
5. Используй OpenAI Responses API через отдельный `SummaryGenerating` adapter.
6. Модель по умолчанию — `gpt-5.6-terra`; разреши настройку экономичного `gpt-5.6-luna`.
7. Если transcript превышает безопасный контекст/лимит приложения, реализуй иерархическое chunk summary с сохранением решений, задач, рисков и таймкодов.
8. Сохрани структурированный результат и отрендеренный Markdown.

## Структура результата

Используй Structured Outputs, если они поддерживаются выбранной актуальной моделью, и валидируй результат локально. Схема должна содержать:

- `title`;
- `overview`;
- `topics[]` с start/end timestamps;
- `decisions[]`;
- `action_items[]`: task, nullable owner, nullable deadline, evidence timestamp;
- `open_questions[]`;
- `risks[]`;
- `key_facts[]`;
- `short_summary`.

Ничего не выдумывай: каждый decision/action item должен иметь evidence timestamp либо явную пометку, что точный таймкод не найден.

## Промпт саммари

Храни prompt template как версионируемый ресурс приложения. Его смысл:

```text
Создай фактическое структурированное резюме рабочего митинга только по предоставленному transcript. Не добавляй отсутствующие решения, имена, сроки или обязательства. Отдели решения от предложений, а задачи — от общих пожеланий. Сохрани язык митинга. Для каждого подтверждённого пункта укажи ближайший таймкод источника. Если говорящий обозначен только как «Участники», не пытайся угадать имя.
```

## Экспорт

Добавь экспорт:

- transcript в Markdown;
- transcript в JSON;
- transcript + summary в Markdown;
- summary JSON.

Экспорт выполняется через NSSavePanel, не содержит API-ключи, внутренние пути базы или диагностические логи.

## Надёжность и стоимость

- Перед отправкой оцени input tokens и ориентировочную стоимость на основе настраиваемой таблицы тарифов; пометь оценку как приблизительную.
- После ответа сохрани фактический usage, если API его вернул.
- Cancellation не удаляет предыдущую успешную summary.
- Повторная генерация создаёт новую версию, а не молча перезаписывает старую.
- Ошибка API не меняет transcript.

## Тесты

Проверь schema validation, chunk aggregation, сохранение evidence timestamps, отсутствие аудио в request, cancellation, retry без дубликатов и все экспортные форматы.

## Критерии приёмки

- Саммари запускается только действием пользователя над completed meeting.
- В API уходит только выбранный текст.
- Результат валидируется и версионируется.
- Экспорт открывается внешними приложениями и не содержит секретов.

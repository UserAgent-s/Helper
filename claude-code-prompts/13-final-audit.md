# Этап 13. Финальный аудит реализации

## Цель

Проведи независимый аудит всей реализации по исходным требованиям, исправь найденные нарушения и создай доказательный отчёт.

## Аудит кода

Проверь весь репозиторий, а не только последние изменения:

1. Ровно три взаимоисключающих режима.
2. Старт всегда в `passive`.
3. В `answers` системное аудио отправляется непосредственно в Realtime во время речи.
4. Whisper/STT отсутствует перед генерацией ответа.
5. UI использует `response.output_text.delta` и не ждёт done.
6. Транскрипция только вопроса запускается асинхронно после валидного ответа.
7. Обычные реплики не попадают в Q&A history.
8. В `recording` весь разговор транскрибируется локально.
9. В `recording` нет Realtime/Responses вызовов до отдельного действия саммари.
10. В `passive` нет capture, mic, Whisper, network и content writes.
11. Исходное аудио не сохраняется по умолчанию.
12. API-ключ только в Keychain и отсутствует в логах/bundle.
13. Старый режим полностью остановлен до запуска нового.
14. Все фоновые задачи имеют владельца, cancellation и ограниченный lifetime.
15. Realtime использует GA schema без beta header.
16. Серверная conversation не накапливает весь митинг.
17. Ошибки переводят систему в безопасное состояние.
18. Удаление/экспорт пользовательских данных работают.
19. Каждый ответ целиком использует основной язык текущего вопроса; ручной override языка и клиентский перевод отсутствуют.
20. Системная инструкция и eval-набор обеспечивают краткий ответ уровня senior software engineer: прямой тезис, техническая корректность, релевантное обоснование и существенные trade-offs/edge cases.
21. Каждый речевой ход после прошлого ответа сохраняется как потенциальный контекст до вопроса; `⟦WAIT_FOR_QUESTION⟧` удаляет только assistant output, а не user input.
22. Любой вопрос в `answers` считается предназначенным пользователю; логика определения другого адресата отсутствует.
23. `Ответить сейчас` доступно до появления текстового ответа и создаёт ровно один manual `response.create` по default conversation без STT/классификатора перед ним.
24. Гонки manual/automatic, повторные клики и pending speech дают не более одного видимого ответа и одного Q&A draft.
25. После ответа, выхода из режима или превышения caps accumulated context очищается и не превращается в полный transcript.

## Поиск незавершённости

Найди и устрани:

- `TODO`, `FIXME`, `fatalError`, `preconditionFailure` в пользовательских путях;
- пустые catch;
- принудительные unwrap без доказанной безопасности;
- detached tasks без контроля;
- неограниченные очереди;
- hardcoded secrets/URLs устаревшего beta API;
- фиктивные success callbacks;
- тесты, которые ничего не утверждают;
- дублирование Realtime schema в нескольких местах.

Не удаляй осмысленные TODO из сторонних generated/dependency файлов; исключи такие каталоги из отчёта и объясни.

## Полный прогон

Выполни:

- генерацию проекта;
- clean build Debug и Release;
- все unit/integration tests;
- latency fake harness;
- статический поиск секретов;
- проверку release bundle;
- ручной smoke checklist для трёх режимов, если macOS GUI доступен.

## Отчёт

Создай `docs/final-audit.md` со следующими разделами:

- commit/worktree state без изменения истории;
- матрица требований и ссылки на реализацию/тесты;
- команды и фактические результаты;
- latency summary p50/p95 на fake и, если доступно, реальном соединении;
- разрешения и privacy review;
- найденные проблемы и выполненные исправления;
- оставшиеся внешние blockers;
- точные шаги запуска MVP.

Не утверждай, что реальный OpenAI latency проверен, если использовался только fake transport.

## Финальные критерии приёмки

- `docs/final-audit.md` подтверждает каждое исходное требование кодом или тестом.
- Нет известных нарушений критического пути `answers`.
- Контекстная задача через несколько речевых ходов используется последующим автоматическим или ручным ответом.
- Кнопка и hotkey `Ответить сейчас` проверены при semantic miss, повторном клике и гонке с автоматическим ответом.
- Нет фоновой обработки в `passive`.
- Нет облачной транскрипции/ответов в `recording`.
- Language evals проходят для русских, английских и смешанных вопросов, включая русские вопросы с английскими техническими терминами.
- Senior-quality eval rubric проходит либо каждый реальный model-eval blocker честно задокументирован; offline prompt-contract тесты обязательны.
- Build и tests проходят либо внешние blockers воспроизводимы и не скрыты.
- Пользователю передан краткий список готового, известных ограничений и точных команд запуска.

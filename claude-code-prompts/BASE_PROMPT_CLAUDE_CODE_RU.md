# Базовый управляющий промпт для Claude Code

Скопируй содержимое этого файла в Claude Code после того, как распакуешь архив `claude-code-prompts-macos-assistant-useragent057.zip` в корень репозитория. Каталог с пошаговыми промптами должен называться `claude-code-prompts`.

---

Ты — ведущий macOS-инженер и технический руководитель проекта `UserAgent057`. Твоя задача — самостоятельно реализовать рабочее приложение для Apple Silicon, последовательно выполняя промпты из каталога `claude-code-prompts`.

## Неизменяемая продуктовая модель

Приложение имеет ровно три взаимоисключающих режима:

1. `answers` — режим быстрых ответов.
   - Захватывай системный звук выбранного приложения, из которого вопрос приходит в наушники.
   - Не ставь распознавание речи в критический путь.
   - Передавай аудио непосредственно в OpenAI Realtime API по мере его появления.
   - Считай всю содержательную речь после предыдущего показанного ответа контекстом следующего вопроса. Объяснение задачи может занимать несколько речевых ходов и пауз; не удаляй эти входные Realtime items, пока вопрос не получил ответ.
   - Каждый вопрос в режиме `answers` считается предназначенным пользователю. Не пытайся определять адресата и не подавляй ответ из-за имени, формы обращения или предполагаемого собеседника.
   - Если вопрос ещё не прозвучал, модель возвращает скрытый sentinel `⟦WAIT_FOR_QUESTION⟧`; UI ничего не показывает, но накопленный контекст остаётся доступен следующему ходу.
   - Начинай выводить ответ в overlay сразу после первого `response.output_text.delta`, не ожидая `response.done`.
   - Приоритеты: минимальная задержка, затем качество; экономия в этом режиме не является приоритетом.
   - Весь ответ давай на основном естественном языке, на котором задан текущий вопрос. Английские названия технологий и фрагменты кода внутри русского вопроса не меняют язык ответа; для действительно смешанного вопроса используй язык его основной смысловой части. Не переводи и не дублируй ответ на другом языке.
   - Отвечай на уровне сильного senior software engineer на собеседовании: сразу дай тезис, затем краткое техническое обоснование и существенный компромисс или граничный случай, только если он относится к вопросу. Ответ должен быть уверенным, production-minded и без выдуманных фактов или опыта.
   - Сохраняй низкую задержку: обычно 2–4 коротких предложения, не более 120 слов, без вступления, пересказа вопроса и служебных фраз.
   - Полный разговор не транскрибируй и не сохраняй.
   - В активном `answers` всегда показывай доступную без появления ответа кнопку `Ответить сейчас` и настраиваемую глобальную горячую клавишу. Если вопрос уже был задан, но модель продолжает ждать, действие должно один раз принудительно вызвать текстовый `response.create` по накопленному Realtime-контексту, без предварительного STT.
   - Если сформирован видимый ответ, асинхронно распознай только ограниченное накопленное окно «контекст задачи + вопрос» для журнала. Эта операция не должна задерживать ответ.
   - Сохраняй только пары «вопрос — ответ» и технические метрики.

2. `recording` — режим записи митинга.
   - Не используй Realtime API и не генерируй ответы.
   - Локально транскрибируй весь системный звук и микрофон с помощью WhisperKit или совместимого локального Whisper runtime.
   - Сохраняй финальный текст с таймкодами и источником `remote`/`local`.
   - Не сохраняй исходное аудио по умолчанию.
   - Саммари является отдельным действием над сохранённым митингом, а не четвёртым режимом.

3. `passive` — отключённый режим.
   - Не захватывай системный звук и микрофон.
   - Не распознавай речь.
   - Не вызывай API.
   - Не сохраняй пользовательский контент.
   - Приложение всегда запускается в этом режиме.

Ни один аудиобуфер, распознаватель или API-клиент не должен продолжать работу после перехода в `passive`.

## Техническая база

- Платформа: macOS 14 или новее, Apple Silicon, приоритет Mac M1.
- Язык: Swift 6 с корректной моделью конкурентности.
- UI: SwiftUI; для неактивирующего окна ответа используй AppKit `NSPanel`.
- Сборка проекта: XcodeGen с `project.yml`, если в репозитории ещё нет поддерживаемого Xcode-проекта.
- Захват: ScreenCaptureKit; на системах, где захват микрофона через ScreenCaptureKit недоступен, используй отдельный `AVAudioEngine`.
- Локальная транскрипция: WhisperKit из `argmaxinc/argmax-oss-swift`; закрепи конкретную стабильную версию зависимости.
- Хранилище: SQLite3, WAL, миграции и FTS5.
- Секреты: API-ключ только в macOS Keychain; ключ запрещено встраивать в приложение, исходники или логи.
- OpenAI: только актуальный GA Realtime API. Не используй legacy beta-заголовки и устаревшие события.
- Модель быстрых ответов: `gpt-realtime-2.1`, `reasoning.effort: low`, только текстовый вывод.
- Прямой поток Realtime: 24 kHz mono PCM16; поток локального Whisper: формат, требуемый выбранной версией WhisperKit.

Перед реализацией конкретного OpenAI-события сверяй его с официальной GA-документацией. Если интернет недоступен, используй спецификацию из промптов и изолируй протокол за типизированным адаптером, чтобы схема могла быть исправлена в одном месте.

## Правила работы

1. Сначала изучи текущий репозиторий, `CLAUDE.md`, незакоммиченные изменения и доступные инструменты. Сохраняй существующую работу пользователя.
2. Не задавай вопросы, если решение можно безопасно принять из этого базового промпта и пошаговых промптов.
3. Не устанавливай глобальные зависимости без явного разрешения. Если отсутствует XcodeGen, создай полный `project.yml` и сообщи точную команду установки, но продолжай всю работу, не требующую генерации проекта.
4. Не создавай заглушки, пустые реализации, `fatalError("TODO")`, фиктивные успешные результаты или комментарии вместо кода.
5. Не удаляй рабочий код ради упрощения задачи. Все изменения должны быть минимальными и целевыми.
6. Не делай git-коммиты, не отправляй изменения и не публикуй сборки без отдельного указания.
7. После каждого этапа запускай относящиеся к нему тесты и сборку. Если проверка невозможна из-за окружения, зафиксируй точную причину и продолжай независимые этапы.
8. Поддерживай `docs/implementation-status.md`: дата, выполненный промпт, изменённые компоненты, команды проверки, результат и оставшиеся риски.
9. Каждый режим должен быть тестируем через внедрение зависимостей; не связывай доменную машину состояний напрямую с системными фреймворками.
10. Любая ошибка запуска или переключения режима должна приводить систему в безопасный `passive`, освобождать ресурсы и показывать понятное сообщение.

## Обязательная финальная проверка

Перед завершением всей работы докажи проверками, что:

- `answers` отправляет аудио напрямую в Realtime и показывает текст до `response.done`;
- локальная транскрипция вопроса не участвует в расчёте ответа;
- несколько объясняющих речевых ходов сохраняются в Realtime как контекст до первого автоматического или принудительного ответа, но очищаются после него;
- `Ответить сейчас` доступно до появления overlay-ответа, использует накопленный контекст и не создаёт второй ответ при гонке с автоматическим ответом;
- `recording` не создаёт Realtime/Responses запросов и транскрибирует весь митинг локально;
- `passive` не держит ScreenCaptureKit, микрофон, Whisper или сетевые задачи;
- переходы между режимами последовательны, идемпотентны и не оставляют фоновых ресурсов;
- полный разговор не сохраняется в `answers`;
- исходное аудио не пишется на диск по умолчанию;
- ключи и содержимое разговоров отсутствуют в логах;
- первый текстовый delta отображается немедленно;
- каждый видимый ответ целиком написан на языке текущего вопроса, а встроенные технические термины не вызывают ошибочного переключения языка;
- системная инструкция режима `answers` задаёт качество ответа уровня senior-разработчика на собеседовании и проверяется русскими, английскими и смешанными сценариями;
- проект собирается, тесты проходят, а `docs/final-audit.md` содержит доказательства.

Начни с чтения `claude-code-prompts/00-product-contract.md` и продолжай до финального аудита без повторного запроса порядка действий.

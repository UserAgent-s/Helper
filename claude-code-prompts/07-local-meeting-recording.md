# Этап 07. Полная локальная транскрипция митинга

## Цель

Реализуй экономный режим `recording`, который локально превращает весь митинг в текст и никогда не генерирует ответы.

## Жизненный цикл

1. При старте создай запись meeting со временем, выбранным приложением и статусом `recording`.
2. Запусти системный звук и микрофон как независимые источники.
3. Не создавай RealtimeClient, ResponsesClient или другие OpenAI network tasks.
4. Запусти локальный WhisperKit pipeline для обоих источников.
5. Показывай live transcript в основном окне, но не открывай answer overlay.
6. При остановке дождись финализации текущих сегментов с ограниченным timeout, сохрани встречу и освободи модель/аудио.
7. После crash при следующем запуске восстанови незавершённую встречу как `interrupted`, не как активную.

## Транскрипция

- Используй multilingual модель `small` по умолчанию для M1.
- Модель и compute options закрепи в настройках.
- Реализуй chunked/streaming обработку с VAD, перекрытием соседних чанков и дедупликацией текста на границах.
- Сохраняй interim text только в памяти/UI; в базу записывай финализированные сегменты.
- Для каждого сегмента сохраняй monotonic start/end и source `remote` или `local`.
- Не обещай имена удалённых участников без diarization. Локальный микрофон можно помечать как `Я`, remote — как `Участники`.
- Добавь расширяемую границу для будущей diarization, но не выдавай эвристику за надёжную идентификацию.

## Производительность

1. Capture callbacks не должны ждать Whisper.
2. Ограничь очередь аудио; примени backpressure и метрики dropped frames.
3. Обрабатывай источники последовательно или с контролируемым параллелизмом, учитывая память M1.
4. При thermal pressure снижай необязательную UI-частоту, но не теряй финальный текст молча.
5. Не загружай две тяжёлые модели, если одну можно безопасно разделять между источниками.

## Хранение аудио

По умолчанию аудио не сохраняется. Если существует отдельная opt-in настройка сохранения аудио, она должна быть выключена по умолчанию, ясно показываться в UI и иметь отдельную политику удаления. Базовая реализация этапа должна полностью работать без записи аудиофайла.

## Тесты

Добавь fixture-based тесты:

- remote и local сегменты получают правильные source;
- перекрывающиеся chunks не дублируют фразу;
- interim текст не попадает в постоянную историю;
- остановка финализирует последний сегмент;
- network client factory не вызывается;
- переход в `passive` прекращает capture и transcription;
- interrupted meeting корректно восстанавливается.

## Критерии приёмки

- Весь доступный разговор сохраняется текстом с таймкодами.
- API ответов/транскрипции не вызывается.
- Answer overlay не появляется.
- Исходное аудио отсутствует на диске по умолчанию.
- После остановки нет продолжающейся локальной инференс-задачи.

# Этап 05. Потоковый overlay ответа

## Цель

Показывай ответ поверх приложения митинга с минимальной UI-задержкой и без перехвата клавиатурного фокуса.

## Реализация окна

1. Создай `NSPanel` с SwiftUI content view.
2. Настрой окно как non-activating, always-on-top и совместимое с Spaces/full-screen приложениями.
3. Окно не должно перемещать фокус из Zoom, Teams, браузера или IDE.
4. Сохраняй позицию, размер, opacity и размер шрифта через настройки.
5. Добавь состояния:
   - скрыто;
   - накапливаем контекст/слушаем текущий ход;
   - ручной ответ ожидает завершения текущей фразы;
   - получен первый текст;
   - потоковый ответ;
   - завершено;
   - ошибка/переподключение.
6. Не показывай входную транскрипцию в режиме `answers`.
7. Не показывай `⟦WAIT_FOR_QUESTION⟧` и не открывай панель текста на контекстных репликах.
8. Пока активен `answers`, показывай компактную non-activating капсулу состояния с кнопкой `Ответить сейчас`, даже когда текстового ответа ещё нет. Продублируй действие в menu bar, чтобы оно оставалось доступно при скрытой капсуле.

## Потоковая отрисовка

1. Подпишись на доменный `AnswerStreamEvent`, а не на сырые JSON-события.
2. После распознавания того, что префикс не является sentinel, отобрази накопленный фрагмент и каждый последующий delta.
3. Не жди `response.output_text.done` или `response.done`.
4. Минимизируй MainActor-работу: агрегируй слишком мелкие delta не дольше одного display frame, но не добавляй искусственный debounce в сотни миллисекунд.
5. Измеряй `first_delta_to_first_paint_ms` через callback после фактического обновления view state.
6. При новой речи немедленно пометь старый ответ отменённым и очисти панель.
7. После завершения оставляй ответ на экране на настраиваемое время; пользователь может закрепить, скопировать или закрыть его.

## Управление

- Добавь глобальную горячую клавишу показа/скрытия overlay без смены режима.
- Добавь настраиваемую глобальную горячую клавишу `Ответить сейчас` с безопасным значением по умолчанию `⌥Return`.
- Кнопка и hotkey вызывают один доменный `forceAnswerNow()`, показывают `Жду окончания фразы…` для pending-состояния и блокируются, когда уже поступает валидный видимый ответ.
- Добавь кнопку копирования финального ответа.
- Добавь настройку положения: верх справа, верх по центру, низ справа, пользовательская позиция.
- В `recording` и `passive` окно ответа скрыто и не подписано на Realtime events.

## Accessibility

- Поддержи VoiceOver labels, reduced motion, contrast и динамический размер текста.
- Не используй только цвет для обозначения состояния.
- Не показывай содержание ответа в системных уведомлениях.

## Тесты

Проверь reducer/view model без реального окна:

- delta поступают до done и сразу меняют текст;
- sentinel полностью скрыт;
- кнопка доступна до первого ответа и не забирает фокус у meeting-приложения;
- повторные клики вызывают один manual trigger;
- `noContext`, `manualResponsePending` и гонка manual/automatic отображаются без мигания или двойного текста;
- отмена очищает старый ответ;
- поздний delta отменённого response ID игнорируется;
- переход в `passive` скрывает окно;
- `recording` не может открыть answer overlay;
- copy использует только финальный видимый текст.

## Критерии приёмки

- Первый валидный delta виден до завершения ответа.
- Overlay не активирует приложение и не забирает фокус.
- Пользователь может принудительно начать ответ, даже если модель ошибочно продолжила ждать вопрос.
- Старые/чужие response events не смешиваются с новым ответом.
- В других режимах окно не обрабатывает содержимое.

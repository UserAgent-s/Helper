# Этап 03. Захват и маршрутизация аудио

## Цель

Реализуй низколатентный захват системного звука выбранного приложения и отдельный захват микрофона с разными маршрутами для `answers` и `recording`.

## ScreenCaptureKit

1. Реализуй выбор источника через системный picker ScreenCaptureKit: приложение, окно или дисплей. Сохраняй предпочтённый bundle identifier, но при каждом запуске проверяй доступность источника.
2. Запрашивай Screen Recording permission только при явном включении `answers` или `recording`, никогда на старте приложения в `passive`.
3. Для `answers` захватывай только системный звук выбранного meeting-приложения. Микрофон по умолчанию не подключай к Realtime.
4. Для `recording` захватывай системный звук и микрофон раздельно, чтобы можно было пометить свои реплики как `local`, а остальные как `remote`.
5. На поддерживаемой системе используй microphone output ScreenCaptureKit; добавь корректный fallback на `AVAudioEngine` для macOS, где этот API недоступен.
6. Не записывай видеокадры. Если API требует output для конфигурации capture, немедленно отбрасывай видео и документируй причину.

## Аудиоформаты

Создай типизированный `AudioFrame` с monotonic timestamp, source, sample rate, channel count и payload.

Подготовь два независимых конвертера:

- Realtime: mono PCM16, 24 kHz, небольшие равномерные фреймы;
- Whisper: формат и sample rate, которые требует закреплённая версия WhisperKit, с единственным контролируемым преобразованием.

Конвертация выполняется вне MainActor. Исключи лишние копирования, неконтролируемый рост буфера и блокировки callback ScreenCaptureKit.

## Буферы

1. Для `answers` используй ограниченный in-memory ring buffer, достаточный для восстановления последнего завершённого вопроса. Начальное значение — 45 секунд.
2. Сегменты размечай по событиям начала/конца речи Realtime и monotonic timestamps.
3. Ring buffer никогда не записывается на диск и очищается при переходе из `answers`.
4. Для `recording` используй bounded async channel с backpressure. При перегрузке регистрируй метрику, не допускай неограниченного потребления памяти.
5. В `passive` оба буфера отсутствуют или пусты, capture sessions остановлены, callbacks больше не публикуют фреймы.

## Разрешения и ошибки

- Создай сервис проверки разрешений Screen Recording и Microphone.
- Показывай конкретные инструкции открытия System Settings.
- После отказа не зацикливай повторный запрос.
- Потеря выбранного приложения, изменение аудиоустройства или sleep/wake должны приводить к контролируемому восстановлению либо безопасному `passive`.

## Тесты

Используй синтетические PCM fixtures и mock clock. Проверь:

- порядок timestamps;
- корректную длительность фреймов после ресемплинга;
- отсутствие переполнения ring buffer;
- разделение `remote` и `local`;
- остановку публикации после cancel;
- backpressure;
- очистку памяти при `passive`.

## Критерии приёмки

- Режим `answers` может начать отправку первого аудиофрейма, не запуская Whisper.
- Режим `recording` получает оба источника раздельно.
- На диск не пишется аудио.
- Callback захвата не блокирует UI и сетевую обработку.
- После остановки нет активных SCStream/AVAudioEngine и новых фреймов.

# MeetingAssistant

Нативное macOS-приложение (Apple Silicon, macOS 14+) для тренировок и собеседований, где помощь разрешена. Три взаимоисключающих режима: `passive`, `answers`, `recording`. В `answers` подсказки генерирует выбранный провайдер — **OpenAI Realtime** или **Anthropic Claude**. Продуктовый контракт и архитектура — `docs/product-contract.md`, `docs/architecture.md`, решения — `docs/adr/`.

Приложение не скрывает себя и оверлей: оверлей — обычное окно поверх других, при демонстрации экрана его может увидеть собеседник. Используйте его только там, где помощь разрешена.

## Быстрый старт (первый запуск)

1. Соберите приложение (раздел «Сборка») или используйте готовую сборку `build/DerivedData/Build/Products/Debug/MeetingAssistant.app`.
2. Запустите. Откроется onboarding: можно сразу ввести ключи OpenAI и/или Anthropic (оба сохраняются в Keychain) и проверить/загрузить локальную модель Whisper.
3. «Настройки» → «Провайдер и модель подсказок» — выберите провайдера и модель (только в Passive).
4. «Настройки» → «Профиль кандидата и вакансия» — заполните профиль (см. ниже). «Память» — проверьте активные профильные области и заметки.
5. Переключитесь в `Answers`. Главное окно показывает провайдера, модель, что уходит наружу, состояние захвата, usage, оценку стоимости и задержки.
6. «Ответить сейчас» — кнопка в меню-баре или `⌥Return`.
7. Чтобы читать подсказки с телефона или второго Mac, включите «Удалённый экран» в настройках и откройте ссылку или QR-код на втором устройстве.

## Два пути подсказок

| | OpenAI Realtime | Anthropic Claude |
|---|---|---|
| Что уходит наружу | системный звук выбранного приложения (непрерывно), инструкции, профиль | только текст: локально распознанная речь с момента последнего ответа, до 2 предыдущих пар вопрос-ответ, инструкции, профиль |
| Распознавание речи | на стороне OpenAI (аудио-модель) | локально, WhisperKit, по фрагментам между паузами (не ждёт остановки) |
| Определение вопроса | серверный VAD + правило `⟦WAIT_FOR_QUESTION⟧` | локальная эвристика по паузе и вопросительным конструкциям + то же правило `⟦WAIT_FOR_QUESTION⟧` |
| API | `wss://api.openai.com/v1/realtime` | `POST https://api.anthropic.com/v1/messages` со `stream: true` (SSE) |
| Модели в списке (проверены 2026-10) | `gpt-realtime-2.1` (по умолчанию), `gpt-realtime-2.1-mini`, `gpt-realtime-2`, `gpt-realtime-mini` | `claude-opus-5-5` (по умолчанию), `claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-fable-5-1` |

Можно указать совместимый model ID вручную («Другая…»). Такая модель помечается «не проверена», её стоимость — «неизвестно», а если провайдер её не знает, сессия останавливается с понятной ошибкой («модель не найдена или недоступна вашей организации»).

Переключение провайдера и модели разрешено только в Passive. Остановка Answers прекращает захват, отменяет сетевой запрос и распознавание, очищает очередь аудио и контекст; запоздавший ответ предыдущего провайдера не показывается. Разговор между провайдерами не переносится; профиль и описание вакансии общие. При ошибке одного провайдера данные другому не отправляются.

Задержку пути Claude складывают: пауза до закрытия фрагмента (≈0.7 с) + локальное распознавание + генерация до первого текста. Стриминг не гарантирует низкую задержку — смотрите измерения в главном окне («Распознавание» и «Вопрос → первый текст», p50/p95).

### Режим «Только по нажатию»

«Настройки» → «Подсказки» → «Когда отвечать» → «Только по нажатию». Вопрос накапливается без автоматических ответов; запрос уходит только по «Ответить сейчас». В OpenAI Realtime аудио всё равно передаётся непрерывно (это свойство транспорта), но сервер не создаёт ответы сам.

## Ключи API

### OpenAI

1. [platform.openai.com/api-keys](https://platform.openai.com/api-keys) → **Create new secret key**. Ключ `sk-…` показывается один раз.
2. В **Billing** пополните баланс — без этого будет ошибка оплаты.
3. Вставьте в «Настройки» → «API-ключи» → «OpenAI API key» → «Сохранить».

### Anthropic

1. [console.anthropic.com](https://console.anthropic.com) → **API Keys** → **Create Key**. Ключ имеет вид `sk-ant-…`.
2. В **Billing** добавьте кредиты или карту.
3. Вставьте в «Настройки» → «API-ключи» → «Anthropic API key» → «Сохранить».

**Claude API ≠ подписка Claude Code/Claude Pro/Max.** Приложение вызывает Claude Messages API напрямую по API-ключу; оплата идёт по тарифам API из консоли Anthropic. Подписка Claude Code или Claude.ai этот API не оплачивает, а OAuth-токены Claude Code приложение не использует и не извлекает.

### Хранение

Оба ключа хранятся в macOS Keychain (`com.local.MeetingAssistant.openai`, `com.local.MeetingAssistant.anthropic`). Если от предыдущей версии в настройках приложения остался ключ OpenAI, при запуске он переносится в Keychain: запись → проверка чтением → только затем удаление старого значения. При любой ошибке старое значение остаётся и продолжает работать, а в Настройках видно, что ключ «в старом хранилище». Ключи не пишутся в логи, диагностику и тестовые отчёты.

С ad-hoc-подписью («Sign to Run Locally») macOS может снова спрашивать доступ к Keychain после пересборки — это плата за Keychain без стабильной подписи. Со стабильной локальной идентичностью (`scripts/sign-and-install.sh` использует сертификат «MeetingAssistant Local Dev») запрос появляется один раз.

## Профиль кандидата

«Настройки» → «Профиль кандидата и вакансия (общие для провайдеров)»:

- **Основной стек** — технологии, с которыми вы реально работаете.
- **Реальный опыт** — только проверяемые факты. Сюда автоматически переносится старое поле «Опыт работы».
- **Реальные кейсы** — кнопка «Вставить шаблон кейса»: ситуация → ограничения → решение → рассмотренные альтернативы → результат. Если результат не измерялся — так и напишите.
- **Области без коммерческого опыта** — модель не будет заявлять продакшен-опыт в них.
- **Целевая роль**, **описание вакансии и темы интервью**.

Пустое поле модель считает неизвестным и не заполняет догадками. Не вставляйте конфиденциальные данные работодателей: профиль уходит выбранному провайдеру вместе с инструкциями.

## Память: профильные области и заметки

Главное окно → «Память». Это память Helper'а, из которой строятся инструкции каждой сессии Answers (ADR 0006, `docs/product-vision.md`).

**Профильные области** задают, каким экспертом отвечает модель: название, роль (кто отвечает) и правила ответа. Активных областей может быть несколько — модель сама выбирает подходящую под вопрос и не упоминает этот выбор. Встроенные области повторяют прежние профили собеседования: PHP / Backend, System Design, Behavioral; старая настройка «Профиль ответа» переносится один раз (конкретный профиль активирует одну область, «Авто» — все три). Свои области добавляются кнопкой «Добавить область». Если активных областей нет, действует прежний режим «Авто».

**Заметки** привязаны к области или общие. Импортируйте резюме, описания проектов, кейсы, подходы к архитектуре (`.md`, `.txt`, `.pdf` до 2 МБ) или добавьте заметку вручную, выбрав область. Каждую заметку можно выключить, переназначить другой области или удалить.

**Папка знаний** `~/Library/Application Support/MeetingAssistant/Knowledge/` синхронизируется автоматически (FSEvents, при запуске, по кнопке «Синхронизировать» и перед каждым стартом Answers): файл `.md`/`.txt` в корне — общая заметка, подпапка — область (создаётся сама и сразу активна; имя сопоставляется без учёта регистра, пунктуации и диакритики, поэтому `php-backend/` попадает в «PHP / Backend»). Удалённый файл удаляет свою заметку; выключенная заметка остаётся выключенной после обновления файла. Так результат исследования, сделанного в Claude Code, попадает в подсказки простым сохранением markdown-файла:

```bash
mkdir -p ~/Library/Application\ Support/MeetingAssistant/Knowledge/Kubernetes
# положите сюда kubernetes-notes.md — область «Kubernetes» появится в окне «Память»
```

- В инструкции входят общие заметки и заметки **активных** областей (до ~40 000 символов суммарно, сверх лимита — обрезка с пометкой); заметки неактивных областей и выключенные заметки не покидают Mac. Окно показывает, сколько заметок уходит, сколько не уходит из-за выключенной области и примерно сколько токенов.
- Контекст фиксируется на старте Answers; изменения в активной сессии помечаются как неприменённые до следующего запуска.

«Настройки» → «Подсказки» → «Память прошлых ответов из Истории» (0–10, по умолчанию 5): последние завершённые пары вопрос-ответ из прошлых сессий добавляются в инструкции, чтобы ответы не противоречили сказанному раньше. 0 — выключено. Эта память общая для всех областей.

Главное окно → строка «Память» показывает активные области, заполнен ли профиль, сколько заметок и прошлых ответов ушло в текущую сессию.

Правила ответа общие для провайдеров (`AnswerInstructionsBuilder`), отличаются только части, зависящие от транспорта (аудио vs транскрипт): язык вопроса; сначала суть, потом детали; для архитектуры — ограничения, выбор, главный компромисс, уместная альтернатива; для производительности — сначала измерение; для инцидентов — сначала ограничение ущерба и защита данных; behavioral — только реальные кейсы; код не заявляется проверенным; никаких гарантий правильности или прохождения интервью.

## Удалённый экран: подсказки на другом Mac или телефоне

«Настройки» → «Удалённый экран» → «Показывать подсказки на другом устройстве» (по умолчанию выключено; ADR 0007). Приложение поднимает два порта в локальной сети: HTTP (по умолчанию 8765) отдаёт веб-страницу, WebSocket (порт + 1) передаёт события. В настройках показываются ссылки вида `http://<IP Mac>:8765/?t=<токен>` для каждого сетевого интерфейса и QR-код первой ссылки — откройте её в браузере второго устройства в той же Wi‑Fi сети. Сервис анонсируется через Bonjour (`_meetinghints._tcp`); macOS 15+ спросит разрешение на доступ к локальной сети.

Веб-страница рассчитана прежде всего на большой экран: слева лента подсказок (новые сверху, стрим виден по мере генерации), справа выбранная подсказка с вопросом, коротким ответом и раскрытием. Кнопки «Ответить сейчас» (`A`), «Подробнее» (`E`), «Сбросить контекст» (`R`) и переключение Passive/Answers работают с телефона так же, как на Mac. На узком экране блоки идут в столбик. Раскрытие («Подробнее») выполняет провайдер активной сессии: Claude — стримом через Messages API, OpenAI — через Responses API моделью саммари (без стрима); результат сохраняется в истории вместе с парой вопрос-ответ.

Границы безопасности: доступ только по токену сопряжения (первое сообщение WebSocket, иначе соединение закрывается через несколько секунд), токен перевыпускается кнопкой; трафик внутри локальной сети не шифруется — не включайте функцию в публичных сетях. Любой, кто знает ссылку с токеном и находится в той же сети, видит подсказки и историю и может переключать режимы. Токен и текст подсказок не пишутся в логи и диагностику. В Passive сервер продолжает работать (чтобы перечитать ответы после разговора), но новых подсказок не возникает и провайдеры не вызываются.

## Какие данные покидают Mac

| Режим | Наружу |
|---|---|
| Passive | ничего к провайдерам; при включённом удалённом экране — состояние и история подсказок устройствам в локальной сети с токеном |
| Answers + OpenAI | системный звук выбранного приложения, инструкции, профиль, активные области и их заметки, память прошлых ответов → OpenAI |
| Answers + Claude | текст распознанной речи с последнего ответа, прошлые пары вопрос-ответ, инструкции, профиль, активные области и их заметки → Anthropic. Аудио не покидает Mac |
| Recording | ничего (локальный Whisper) |
| Саммари (по кнопке, с подтверждением) | транскрипт встречи → OpenAI Responses API |

Локально сохраняются пары вопрос-ответ Answers и транскрипты Recording (SQLite в `~/Library/Application Support/MeetingAssistant/`). Аудио Answers на диск не пишется никогда; WAV в Recording — только при явно включённом «Сохранять аудио на диск». Подробно — `docs/privacy.md`.

## Расход и диагностика

Главное окно показывает usage текущей сессии (вход/кеш/запись в кеш/аудио/выход/reasoning — то, что вернул провайдер), оценку стоимости с источником и датой тарифа, задержку распознавания, время «вопрос → первый текст», число ошибок и переподключений. Если usage или тариф неизвестен — «неизвестно», а не ноль. Оценка не является счётом.

«Настройки» → «Расходы»: порог на сессию в $ и действие — «Только предупредить» (мягкий порог) или «Остановить сессию». Остановка срабатывает после получения usage, поэтому запрос, уже находящийся в обработке, может превысить порог; для модели без тарифа порог не может сработать (это показывается). Жёсткий денежный лимит задаётся только в консоли провайдера.

«Диагностика» сохраняет JSON без аудио, текста разговора, профиля и ключей. Текст вопросов/ответов и транскрипты добавляются только при включённом «Настройки» → «Диагностика» → «Включать текст…».

## Сравнительный тренировочный тест провайдеров

1. Подготовьте 10–15 вопросов (PHP/Backend, System Design, Behavioral, RU и EN), запишите их или прочитайте вслух из видео/второго устройства, проигрываемого через выбранное приложение-источник.
2. Установите одинаковые «Длину ответа» и «Профиль ответа», режим «Автоматически».
3. Passive → выберите OpenAI → Answers → прогоните набор → «Диагностика» (сохраните JSON).
4. Passive → выберите Claude → Answers → тот же набор → «Диагностика».
5. Сравните в JSON `answerSession`: `questionToFirstTextP50Ms/P95Ms`, `recognitionLatencyP50Ms` (только Claude), `estimatedCostUSD`, `errorCounts`; качество ответов — в «Истории».
6. Повторите в режиме «Только по нажатию», чтобы отделить качество ответов от качества автоопределения вопроса.

## Сборка

Требования: Apple Silicon, macOS 14+, Xcode с Swift 6, XcodeGen (`brew install xcodegen`).

```bash
make verify-fast
```

или вручную:

```bash
swift build && swift test
xcodegen generate
xcodebuild -project MeetingAssistant.xcodeproj -scheme MeetingAssistant -configuration Debug -derivedDataPath build/DerivedData build
xcodebuild -project MeetingAssistant.xcodeproj -scheme MeetingAssistant -configuration Debug -derivedDataPath build/DerivedData test
```

Тесты приложения (`xcodebuild test`) запускают его как test host в изолированном окружении (`MEETINGASSISTANT_ISOLATED_ROOT`, отдельный домен настроек и namespace Keychain) — ваши настройки, история и ключи не читаются и не меняются. Тем же способом можно вручную запустить приложение для проверки интерфейса:

```bash
MEETINGASSISTANT_ISOLATED_ROOT=/tmp/ma-sandbox build/DerivedData/Build/Products/Debug/MeetingAssistant.app/Contents/MacOS/MeetingAssistant
```

Платные запросы к реальным API в автоматических тестах не выполняются: OpenAI и Anthropic проверяются через фейковые транспорты. `make verify-real` описывает ручной протокол проверки с реальными ключами.

## Структура

- `Package.swift` — пакет `MeetingAssistantCore`: `Domain`, `AudioCapture`, `RealtimeClient` (OpenAI), `AnthropicClient` (Claude), `Transcription`, `Persistence`, `SecurityStore`, `Diagnostics`, `Summary`, `OverlayReducer`.
- `Sources/App`, `Sources/OverlayUI`, `Sources/HistoryUI` — уровень приложения.
- `project.yml` — спецификация XcodeGen (bundle id `com.local.MeetingAssistant`).
- `Resources/MeetingAssistant.entitlements` — Hardened Runtime; **App Sandbox выключен** (см. `docs/adr/0005-keychain-and-app-sandbox.md`), `network.client`, `device.audio-input`.

## Локальная модель Whisper

По умолчанию `openai_whisper-small`. Нужна для `Recording` и для `Answers` через Claude. Скачивается при первом использовании (или кнопкой в onboarding) и кешируется вне каталога приложения. Пока модель загружается, главное окно показывает «загрузка модели распознавания…».

## Release, подпись, нотаризация

```bash
xcodegen generate
xcodebuild -project MeetingAssistant.xcodeproj -scheme MeetingAssistant -configuration Release archive -archivePath build/MeetingAssistant.xcarchive
```

Подпись Developer ID и нотаризация требуют вашей учётной записи Apple Developer и здесь не выполнялись. Нотаризация требует Hardened Runtime (включён) и не требует App Sandbox.

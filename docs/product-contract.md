# Продуктовый контракт UserAgent057

## Режимы

Приложение имеет ровно три взаимоисключающих режима. Активен всегда ровно один.

```swift
enum AppMode: Sendable {
    case passive
    case answers
    case recording
}
```

Приложение стартует в `passive`.

### `passive`

- Не захватывает системный звук и микрофон.
- Не распознаёт речь.
- Не вызывает сетевые API.
- Не сохраняет пользовательский контент.

### `answers`

- Источник аудио: только системный звук выбранного приложения (по умолчанию).
- Критический путь: `ScreenCaptureKit → PCM16 24 kHz mono → Realtime WebSocket (gpt-realtime-2.1, reasoning.effort=low, text-only) → response.output_text.delta → NSPanel`.
- Локальный Whisper **исключён** из критического пути ответа. Он используется только асинхронно, после того как видимый ответ уже начал показываться, для ограниченного окна «контекст задачи + вопрос» ради журнала Q&A.
- Накопление контекста: несколько речевых ходов и пауз считаются продолжающимся объяснением задачи. Пока явного вопроса нет, модель обязана вернуть скрытый sentinel `⟦WAIT_FOR_QUESTION⟧`; UI ничего не показывает, но входные Realtime items не удаляются.
- Любой вопрос в `answers` считается адресованным пользователю. Определение адресата не выполняется и не влияет на решение отвечать.
- После того как сформирован видимый ответ (автоматический или через «Ответить сейчас»), накопленный входной контекст очищается — следующий вопрос начинает накопление заново.
- Отмена ответа новой речью собеседника удаляет только выход этого ответа; накопленный вопрос сохраняется (ADR 0008).
- `Ответить сейчас`:
  - доступно (кнопка + настраиваемая глобальная горячая клавиша) даже до появления overlay-ответа;
  - использует уже накопленные Realtime conversation items;
  - добавляет один system item с инструкцией принудительного ответа и вызывает ровно один `response.create` без поля `instructions`, чтобы не заменить инструкции сессии (ADR 0008, S0.4);
  - не предваряется STT или вторым модельным запросом;
  - гонка с автоматическим ответом разрешается идемпотентно: первый валидный `response` побеждает, второй/поздний — игнорируется или отменяется.
- Ответ на экране начинается сразу по первому `response.output_text.delta`, не дожидаясь `response.done`.
- Вне сессии ассистента полный разговор не сохраняется: только пары «вопрос — ответ» и технические метрики задержки. Внутри сессии сохраняется стенограмма (ADR 0006, S4.4).
- Исходное аудио не пишется на диск.

#### Контракт содержания ответа

- Ответ целиком на основном естественном языке текущего вопроса.
- Английские названия технологий/фрагменты кода внутри вопроса на другом языке не считаются сменой языка.
- Для действительно смешанного вопроса — язык той части, что несёт основной смысл.
- Не переводится и не дублируется на другом языке.
- Уровень: сильный senior software engineer на собеседовании — сразу тезис, затем краткое техническое обоснование, и только релевantный компромисс/edge case.
- Обычно 2–4 коротких предложения, не более 120 слов. Без вступления, без пересказа вопроса, без служебных фраз.

### `recording`

- Источники аудио: системный звук + микрофон.
- Не использует Realtime API, не вызывает генерацию ответов.
- Локальная транскрипция всего аудио через WhisperKit (VAD/чанкинг → финальные реплики).
- Каждая финальная реплика сохраняется с таймкодом и источником (`remote` — системный звук/удалённый участник, `local` — микрофон пользователя).
- Исходное аудио по умолчанию не сохраняется.
- Саммари — отдельное действие над уже сохранённым митингом, не отдельный режим.

## Утверждённые изменения (план v3, 2026-11-08)

Эти пункты меняют контракт выше по мере выполнения этапов. Пока этап не выполнен, действует прежний текст. Отметка о выполнении ставится в `docs/implementation-status.md`.

- M1, ADR 0004: источник аудио в `answers` по умолчанию весь системный звук без самого приложения. Пресет «Только Google Chrome» и исключения задаются в настройках. Whisper в `answers` не запускается, текст вопроса берётся из транскрипции входа Realtime.
- M3, ADR 0004: канал «Я» (микрофон владельца) в `answers` по отдельной настройке, с эхо-политикой по маршруту вывода.
- M4, ADR 0006: внутри сессии ассистента в `answers` сохраняется полная стенограмма. Вне сессии сохраняются только Q&A. Выполнено в S4.4: пункты «полный разговор не сохраняется» ниже действуют только вне сессии.
- M5–M6, ADR 0007: раскрытие ответов через Claude, профиль владельца из MD-папки, перевод EN→RU в стенограмме. В пресете «Оператор» ответ даётся на RU и EN. Правило «не переводится и не дублируется» остаётся для пресета интервью и подготовки.
- M2 и M2b, ADR 0005: второй экран в локальной сети и роль «Подключаемый».

## Переходы между режимами

- Переход всегда: **остановить текущий режим полностью → дождаться освобождения ресурсов (audio capture, sockets, recognizer) → запустить новый режим**.
- Любая ошибка запуска/переключения приводит систему в `passive`, освобождает ресурсы, показывает понятное сообщение.
- Переходы идемпотентны: повторный запрос того же режима не создаёт дублирующихся ресурсов.

## Политика данных

- Старт всегда в `passive`.
- Исходное аудио не хранится по умолчанию ни в одном режиме.
- В `answers` вне сессии ассистента не хранится полный разговор — только Q&A-пары и метрики. Внутри сессии хранится стенограмма (ADR 0006, S4.4).
- В `recording` не вызывается ни Realtime, ни Responses API.
- Саммари запускается пользователем вручную после завершения записи.
- API-ключ хранится локально в `UserDefaults` приложения (`UserDefaultsSecretStore`); не встраивается в бинарник, исходники или логи. См. `docs/privacy.md` про отказ от Keychain при ad-hoc-подписи.

## Целевые метрики (LatencyRecording)

| Метрика | Описание |
|---|---|
| `speech_end_to_first_delta_ms` | от конца речи до первого `response.output_text.delta` |
| `first_delta_to_first_paint_ms` | от первого delta до отрисовки в NSPanel |
| `response_total_ms` | полное время ответа |
| `mode_stop_ms` | время полной остановки предыдущего режима при переключении |
| `manual_trigger_to_first_delta_ms` | от нажатия «Ответить сейчас» до первого delta |
| `context_duration_ms` + `trigger kind` (`automatic`/`manual`) | длительность накопленного контекста и тип триггера ответа |
| потерянные/дублированные аудиофреймы | целостность аудиопотока |

## Границы протоколов домена

Системные фреймворки (ScreenCaptureKit, AVFoundation, WhisperKit, URLSession/WebSocket, UserDefaults/Keychain) не проникают в доменные типы. Домен общается через собственные `Sendable`-типы и протоколы:

- `ModeControlling`
- `SystemAudioCapturing`
- `MicrophoneCapturing`
- `RealtimeAnswering`
- `AnswerTriggering`
- `LocalTranscribing`
- `MeetingRepository`
- `QuestionAnswerRepository`
- `SummaryGenerating`
- `SecretStoring`
- `LatencyRecording`

Подробности протоколов и типов — в `docs/architecture.md`.

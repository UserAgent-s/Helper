# ADR 0007: Структурированные подсказки и удалённый экран по локальной сети

Дата: 2026-11-02. Статус: принято.

## Контекст

Состояние оверлея — видимость и одна строка текста; история — пары вопрос-ответ. Цель требует разделять мгновенные подсказки и длинные раскрытия, раскрывать по клику и показывать всё на другом устройстве (`docs/product-vision.md`).

Рассматривались для транспорта на другое устройство:

1. **Встроенный сервер в приложении (Network.framework), веб-интерфейс в браузере другого устройства.** Без зависимостей, работает на любом устройстве с браузером.
2. **Сервер на SwiftNIO/Vapor/Hummingbird.** Один порт, зрелый HTTP, но тяжёлая зависимость и долгая сборка.
3. **Облачный ретранслятор.** Нужен сервер, контент покидает локальную сеть; откладывается до этапа 18.

## Решение

- `Hint { id, createdAt, question?, text, status, expansion? }` и лента `HintFeed` (actor, Domain): строится из `AnswerStreamEvent` активного провайдера, привязывает вопрос по обновлениям `QuestionAnswerLogger` (совпадение текста завершённого ответа), хранит последние N подсказок сессии и отдаёт `AsyncStream<HintFeedEvent>` со снимком при подписке.
- Раскрытие — отдельный запрос `HintExpanding` тем же провайдером, что и активная сессия: Claude через Messages API (стрим), OpenAI через Responses API текстовой моделью саммари (без стрима в MVP). Раскрытие не трогает критический путь мгновенной подсказки и сохраняется в `qa_entries.expansion_text`.
- Вариант 1 для транспорта. Два слушателя `NWListener`: HTTP на порту P отдаёт встроенную страницу, WebSocket (`NWProtocolWebSocket`) на порту P+1 транслирует JSON-события и принимает команды. Один порт потребовал бы собственной реализации handshake и фрейминга WebSocket; два порта дешевле и используют системную реализацию.
- Доступ: первое сообщение клиента — `auth` с токеном сопряжения, иначе соединение закрывается; токен показывается в приложении как ссылка и QR-код и может быть перевыпущен. Сервер слушает все интерфейсы и анонсируется через Bonjour `_meetinghints._tcp`; TLS в локальной сети не используется в MVP.
- Жизненный цикл: сервер работает, пока включён переключатель «Удалённый экран» (по умолчанию выключен), независимо от режима, чтобы страницу можно было открыть до старта Answers. В `passive` новые подсказки не создаются и провайдеры не вызываются; авторизованный клиент по-прежнему видит состояние сессии и историю подсказок (это данные самого пользователя на его устройстве), чтобы перечитать ответы после разговора.

## Следствия

- Правило контракта «`passive` не вызывает сетевые API» уточняется: оно относится к исходящим вызовам провайдеров; входящий слушатель локальной сети для собственных устройств пользователя допустим при явном включении. Контракт и `docs/privacy.md` обновлены.
- Нужны `com.apple.security.network.server`, `NSLocalNetworkUsageDescription` и `NSBonjourServices` (macOS 15 запрашивает доступ к локальной сети).
- Любой, кто знает токен и находится в той же сети, видит подсказки и может переключать режимы; токен не пишется в логи и диагностику.
- Локальный оверлей продолжает работать от `AnswerStreamEvent`; переход оверлея на ленту подсказок с раскрытием — отдельный шаг после MVP.

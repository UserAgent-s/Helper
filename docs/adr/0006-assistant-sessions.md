# ADR 0006: Сессия ассистента — контейнер над режимами, а не четвёртый режим

## Статус

Принято (2026-11-08). Реализация в M4.

## Контекст

- Владелец хочет запускать и останавливать сессии и хранить их историю (R10).
- ADR 0001 закрепляет ровно три взаимоисключающих режима. `qa_entries` сейчас не связаны ни с какой сессией (`SQLiteMigrations.swift`, схема v1).

## Решение

1. `AssistantSession` с состояниями Start и Stop живёт над `ModeCoordinator`. Внутри одной сессии может быть несколько отрезков разных режимов (`session_spans`).
2. Хранение: `meetings.kind = session`, `session_spans`, `session_id` у `qa_entries`, стенограммы «Собеседник» и «Я», раскрытия, тексты экрана, закладки.
3. Пока сессия активна, в `answers` сохраняется полная стенограмма. Это меняет прежний пункт продуктового контракта «полный разговор не сохраняется» и включается только внутри сессии.
4. Срок хранения (`historyRetentionDays`) реально применяется: старые сессии удаляются вместе с аудио и FTS-строками.

## Альтернативы

- Четвёртый режим `session`. Отвергнуто: ломает инварианты ADR 0001 и тесты переходов.

## Последствия

- Миграция v2 с резервной копией до неё.
- Поиск по истории: FTS5 unicode61 плюс trigram (см. ADR 0008).

## Критерии пересмотра

Если понадобятся параллельные сессии или сессии на клиентском устройстве.

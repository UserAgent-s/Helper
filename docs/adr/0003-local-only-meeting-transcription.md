# ADR 0003: Локальная транскрипция митингов, без облачных API в `recording`

## Статус

Принято.

## Контекст

Режим `recording` предназначен для полной записи митинга (потенциально содержащей чувствительную бизнес-информацию, персональные данные участников). Отправка полного аудио или полной транскрипции в облачный API создаёт риск приватности и требует согласия всех участников, которое приложение не может гарантированно получить.

## Решение

`recording` выполняет транскрипцию целиком локально через WhisperKit (`argmaxinc/argmax-oss-swift`, версия зафиксирована в зависимостях). Ни Realtime API, ни Responses API не вызываются в этом режиме. Сохраняются только финальные текстовые реплики с таймкодами и источником (`remote`/`local`), а не исходное аудио (по умолчанию). Саммари — отдельное, явно инициированное пользователем действие над уже сохранённой локальной транскрипцией; оно не превращает `recording` в четвёртый режим и не требует переключения режима приложения для своего выполнения (оно оперирует над уже завершённым митингом).

## Последствия

- `recording` не имеет сетевой зависимости для своей основной функции (запись+транскрипция); это делает его пригодным для конфиденциальных встреч.
- Саммари (этап 09) — единственное место в `recording`-related функциональности, которое обращается к сети, и оно явно за пределами `recording`-режима: вызывается только после того, как митинг завершён и сохранён.
- WhisperKit должен работать полностью офлайн на устройстве; выбор конкретной модели/весов фиксируется отдельно при бутстрапе зависимостей (этап 01) с указанием точной версии.
- Тесты домена могут проверять "нет сетевых вызовов в recording" через fake `RealtimeAnswering`/`SummaryGenerating`, которые падают при любом вызове во время активного `recording`.

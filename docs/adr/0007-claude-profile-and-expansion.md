# ADR 0007: Claude для раскрытия ответов и профиль владельца из MD-папки

## Статус

Принято (2026-11-08). Реализация в M5. Шов `ProfileKnowledgeProviding` появляется в S0.6.

## Контекст

- Нужны подробные ответы через Claude с ключом владельца (R3) и знания из его MD-файлов (R8).
- Папка профиля владельца: 14 текстовых файлов, *.md весят 160 КБ, `01_ABOUT_ME_ALL_IN_ONE.md` (68 КБ) сводит большую часть остальных, есть три варианта CV. В файлах описаны правила правдивости и приоритет источников.
- Сейчас контекст о владельце — одна строка `backgroundContext` в UserDefaults (`AppSettingsStore.swift:90-93`), которая вставляется в instructions (`RealtimeInstructions.swift:6-24`).

## Решение

1. `ProfileKnowledgeProviding`: `snapshot()`, `pinnedCore(tokenBudget:)`, `search(_:)`, `canonicalDocuments()`. В v1 реализация локальная: MD-папка плюс SQLite. Будущий отдельный проект памяти подключается как ещё одна реализация того же контракта и проходит те же contract-тесты.
2. Канонический набор по умолчанию: `02_CURRENT_PROFILE.md` › `01_ABOUT_ME_ALL_IN_ONE.md` › `03_OPEN_QUESTIONS.md`. Факты из `03` считаются неподтверждёнными. `Sources/` и `CV/` исключаются по `MANIFEST.json`, их можно включить галочками.
3. Claude получает весь канон блоками `search_result` с включёнными цитатами, кеш с TTL 1 час стоит до изменчивой части. Правила правдивости — отдельный постоянный системный блок. Поиск по истории даётся инструментами `search_session` и `search_memory`.
4. Модели: Sonnet для раскрытия по умолчанию, Opus по выбору, Haiku для перевода и сводок. Идентификаторы моделей и `anthropic-version` сверяются с документацией перед S5.3.
5. Ключ Anthropic хранится так же, как ключ OpenAI (см. privacy.md).

## Альтернативы

- Весь профиль в instructions Realtime. Отвергнуто: дорого на каждом ходе и медленно.
- Только выжимка для всех путей. Отвергнуто: даёт ложное «нет опыта».

## Последствия

- Профиль уходит в Anthropic. Это новый исходящий поток данных, он описан в privacy.md.
- Профиль не попадает в логи и экспорт диагностики, а клиентскому устройству передаются только ответы.

## Критерии пересмотра

Если канон перестанет помещаться в кеш дешевле, чем поиск, или если будет готов отдельный проект памяти.

## Дополнение S5.1 (2026-11-10)

- `SecretStoring` принимает `SecretProvider {openAI, anthropic}`. Расширение протокола без параметра означает `.openAI`, поэтому существующие вызовы (Realtime, саммари) не изменились.
- Ключ OpenAI остаётся под прежним ключом UserDefaults и читается без миграции. Для Anthropic заведён новый ключ. В `KeychainSecretStore` (в приложении не используется) у Anthropic отдельный service `<service>.anthropic`.
- Валидатор: OpenAI — `sk-`, но не `sk-ant-`; Anthropic — `sk-ant-` и не меньше 20 символов. `APIKeyFormatValidator.check` сообщает, что ключ вставлен не в то поле.

## Дополнение S5.2 (2026-11-10)

- Контракт (`Domain/ProfileKnowledge.swift`): `snapshot()`, `realtimeDigest()`, `relevantContext(for:tokenBudget:)`, `transcriptionKeywords()`, `fingerprint()` через расширение. `pinnedCore`/`search`/`canonicalDocuments` из пункта 1 не введены: их роль в v1 выполняет `relevantContext`, который отдаёт весь выбранный профиль.
- Выбор файлов (поправка v3 к R8): по умолчанию файлы верхнего уровня с префиксами `01_`, `02_`, `03_`; если таких нет — все `*.md` верхнего уровня. `00_START_HERE.md`, `Sources/`, `CV/` включаются галочками. `MANIFEST.json` не разбирается: подпапки и так не выбраны по умолчанию.
- Порядок документов — по относительному пути, а не по приоритету правдивости 02 › 01 › 03; приоритет будет задан правилами в системном блоке Claude (S5.3/S5.4).
- Без выбранной папки профиль = текст «Опыт работы». Выбранная, но недоступная папка — явная ошибка, а не тихий откат на старый фон.

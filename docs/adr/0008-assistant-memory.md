# ADR 0008: Память ассистента в четырёх уровнях

## Статус

Принято (2026-11-08). Шаги MEM-0…MEM-10 распределены по M0–M5.

## Контекст

Проверено по коду:

- После каждого видимого ответа удаляется весь контекст разговора Realtime (`AnswerContextWindow.takeAllForCleanup`, `OpenAIRealtimeAnswerClient.swift:362`).
- При отмене ответа новой речью (`status == "cancelled"`, `OpenAIRealtimeAnswerClient.swift:342-348`) удаляется и накопленный вопрос. Это нарушает правило CLAUDE.md «context clears only after a completed answer, never mid-stream».
- Элементы старше 300 с выбрасываются без сжатия, и только при появлении нового элемента (`AnswerContextWindow.swift:15,46-58`).
- FTS5 работает на unicode61 без стемминга: «очередь» не находит «очереди», «КАФКА» не находит «Kafka» (проверено на SQLite 3.54).
- Сессия Realtime длится не больше 60 минут.
- Системная SQLite собрана с `OMIT_LOAD_EXTENSION`, поэтому sqlite-vec недоступен.
- Сервер запускает автоответ на `input_audio_buffer.committed` (`create_response: true`), а текст реплики приходит позже.

## Решение

| Уровень | Что | Где | Очистка |
|---|---|---|---|
| L0 звонок | Накопленный вопрос, перенос последних 1–2 Q&A, `CallState` (сводка, сущности, реестр Q&A, обещания) | Realtime-разговор и actor `CallStateTracker` со снимками в SQLite | Вопрос — после завершённого ответа, при Reset или по окну (600 с, настраивается). Вытесняемое сначала сворачивается в сводку. Отмена ответа удаляет только его output-items |
| L1 сессия | Стенограммы, Q&A, раскрытия, закладки, итоги | SQLite (ADR 0006) | По сроку хранения |
| L2 между сессиями | Одобренные владельцем факты: люди, компании, обещания, «что я рассказывал о себе» | SQLite `memory_facts` | Владельцем. Факты о третьих лицах — по сроку и вместе с сессией |
| L3 знания | Канон профиля, пакет сессии | MD-папка и индекс фрагментов в SQLite | Переиндексация между сессиями |

Правила:

1. Ассистент сам ничего не записывает в долговременную память: факты попадают туда только после одобрения владельцем.
2. Автоответ Realtime получает ядро профиля (≤4K), `CallState` и фрагменты, найденные по прошлым репликам («на шаг позади»). «Ответить сейчас» и клики ищут точно по тексту вопроса. Отключение автозапуска ответа проверяется экспериментом в M5. Инструмент `search_memory` в Realtime доступен только за флагом.
3. Поиск гибридный: FTS5 unicode61 плюс trigram, синонимы и английские ключевые слова к фрагментам, которые Claude генерирует при индексации. Слияние через RRF. Эмбеддинги (векторы в BLOB, перебор через vDSP) включаются только с согласия владельца.
4. Каждое утверждение об опыте владельца ссылается на «файл › раздел». Если в найденном чего-то нет, это не значит «нет опыта»: модель так и говорит, что в профиле нет.
5. Качество меряется набором контрольных вопросов на синтетическом профиле в `verify-fast` и локальным прогоном по настоящей папке, который не коммитится. Метрики: recall@5, доля ложных «нет опыта», доля выдуманных цифр.

## Альтернативы

- Отдать всё будущему отдельному проекту памяти. Отвергнуто: без L0 и L3 версия 1 работает плохо уже сейчас. Шов сохраняется.
- sqlite-vec. Отвергнуто из-за `OMIT_LOAD_EXTENSION`.

## Последствия

- Каждое изменение памяти отражается в этом ADR и в `docs/implementation-status.md`.
- Тест `newSpeechCancelsVisibleAnswerAndClearsContext` инвертируется в S0.4.

## Критерии пересмотра

После первого прогона контрольного набора в M5 или при подключении отдельного проекта памяти.

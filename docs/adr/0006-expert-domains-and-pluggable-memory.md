# ADR 0006: Профильные области и подключаемая память

Дата: 2026-11-02. Статус: принято.

## Контекст

Инструкции подсказок жёстко описывали одну роль (senior backend на собеседовании) и четыре фиксированных профиля `InterviewAnswerProfile`. База знаний «Мой опыт» была плоским списком заметок, которые целиком входили в каждую сессию. Цель (`docs/product-vision.md`) — мульти-эксперт: несколько областей знаний одновременно, свои области пользователя и загрузка знаний из файлов, которые пишет Claude Code.

Рассматривались:

1. **Профильные области как сущности + заметки с привязкой к области.** Активные области и их заметки входят в инструкции; модель выбирает область под вопрос.
2. **Оставить один профиль и теги на заметках.** Проще, но не даёт разных ролей и правил ответа для разных областей.
3. **Отдельный системный промпт на область с переключением по вопросу через второй вызов модели.** Второй вызов на критическом пути противоречит приоритету задержки (ADR 0002).

## Решение

Вариант 1.

- `ExpertDomain { id, name, role, guidance, isActive, sortOrder, updatedAt }` в Domain, репозиторий `ExpertDomainRepository`, таблица `expert_domains` (миграция v3). Встроенные области с фиксированными UUID повторяют тексты прежних профилей; сидирование идемпотентно и переносит старую настройку: `phpBackend`/`systemDesign`/`behavioral` активируют одну область, `automatic` — все три.
- `KnowledgeNote.domainID: UUID?` (NULL = общая заметка) и `KnowledgeNote.origin` (`manual` | `folder`). Удаление области обнуляет `domain_id` её заметок, а не удаляет их.
- `KnowledgeContextBuilder.build(notes, domains, budget)` включает общие заметки и заметки активных областей, помечая область в заголовке; заметки неактивных областей не входят в текст и не покидают Mac.
- `AnswerInstructionsBuilder` получает `[ExpertDomain]` вместо `InterviewAnswerProfile`: секция «Expert areas» перечисляет роль и правила каждой активной области и требует молча выбрать подходящую под вопрос. Пустой список даёт прежнее поведение «Авто».
- Наблюдаемая папка `Knowledge/` в каталоге данных: подпапка = область (создаётся при первом появлении, активная), файл `.md`/`.txt` = заметка с детерминированным id от относительного пути; удалённые файлы удаляют свои заметки, выключенность заметки пользователем сохраняется при обновлении файла. Синхронизация: при запуске, по FSEvents с задержкой, по кнопке и перед стартом Answers в `prepare`.
- `KnowledgeLibrary` (actor, Domain) — единая точка для областей, заметок, сидирования и синхронизации; UI и `prepare` работают только через неё.

## Следствия

- `AnswerSessionConfiguration.answerProfile` заменён на `expertAreas: [String]`; отпечаток контекста учитывает области, поэтому смена набора областей во время сессии помечается как неприменённая.
- Настройка «Профиль ответа» удалена из Settings; управление областями — в окне «Память».
- Бюджет символов общий на все активные области; при переполнении заметки обрезаются с пометкой, как раньше. Поиск по заметкам (FTS5) для больших библиотек отложен до появления реальной потребности.
- Память прошлых ответов остаётся общей и не фильтруется по области.

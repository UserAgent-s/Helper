# ADR 0001: Три взаимоисключающих режима вместо гибкого набора флагов

## Статус

Принято.

## Контекст

Приложение могло бы быть смоделировано как набор независимых булевых флагов (захват включён/выключен, распознавание включено/выключено, Realtime включён/выключен). Это создаёт комбинаторное пространство состояний, часть которых нарушает приватность (например, распознавание работает, пока пользователь думает, что приложение выключено) или архитектурные инварианты (Realtime и локальный Whisper работают одновременно на одном аудиопотоке).

## Решение

Ввести закрытый `enum AppMode { case passive, answers, recording }`. Ровно один режим активен в любой момент. Переход между режимами всегда проходит через полную остановку текущей сессии перед стартом новой (см. `docs/architecture.md`, диаграмма состояний). Никакого четвёртого фонового режима, никаких скрытых комбинаций флагов.

Внутренние состояния ожидания (`⟦WAIT_FOR_QUESTION⟧`) и ручного триггера (`Ответить сейчас`) — это состояния/действия ВНУТРИ `answers`, а не отдельные режимы.

## Последствия

- Каждый adapter и координатор может полагаться на инвариант "не более одного активного источника аудио/сети одновременно".
- UI переключатель режима отображает ровно 3 состояния.
- Тестирование доменной машины состояний сводится к конечному набору переходов, все проверяемы.
- Любая ошибка обязана резолвиться в `passive`, а не в неопределённое "частично активное" состояние.

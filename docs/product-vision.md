# Видение продукта: мульти-эксперт с подключаемой памятью и удалённым экраном

Зафиксировано 2026-11-02 по решению владельца проекта. Этот документ описывает цель, к которой движется MeetingAssistant после этапов 00–13, и порядок этапов 14–18. Продуктовый контракт трёх режимов (`docs/product-contract.md`) остаётся в силе; видение расширяет его, а не заменяет.

## Цель

Создать Helper, который во время живого разговора помогает человеку думать и отвечать как эксперт в нужной области, опираясь на собственную память пользователя, и показывает структурированные подсказки на удобном устройстве рядом: другом Mac, планшете или телефоне.

Первый сценарий — прохождение технических собеседований. Он уже работает и остаётся эталоном задержки и качества. Следующие сценарии (техническое интервью клиента, консультация, экзамен, рабочая встреча в незнакомой области) должны получаться подключением другой профильной области и другой памяти, без изменения кода пайплайна.

## Три опоры

### 1. Мульти-эксперт: профильные области

Профильная область (`ExpertDomain`) — это роль эксперта, правила ответа и привязанные к ней знания. Активно может быть несколько областей одновременно; модель сама выбирает подходящую под вопрос, как сейчас делает профиль «Авто». Встроенные области повторяют текущие профили собеседования: PHP / backend, System design, Behavioral. Пользователь добавляет свои.

Профиль кандидата (реальный опыт, кейсы, вакансия) остаётся общим для всех областей: это факты о человеке, а не об области знаний.

### 2. Память, которую можно подключать

Память состоит из трёх слоёв, каждый отключаем и каждый виден пользователю до отправки:

- **Заметки знаний**, привязанные к области или общие. Загружаются вручную (`.md`, `.txt`, `.pdf`) или автоматически из наблюдаемой папки `Knowledge/` в данных приложения: подпапка = область, файл = заметка. Так результат исследования, сделанного в Claude Code, попадает в подсказки простым сохранением markdown-файла.
- **Профиль кандидата** — общий.
- **Память прошлых ответов** из истории вопрос-ответ — общая, с ограничением по количеству.

Активные области и их заметки входят в инструкции провайдеру в пределах бюджета символов; неактивные не покидают Mac. Контекст фиксируется на старте Answers, изменения помечаются как неприменённые до следующего запуска — это существующее правило.

### 3. Структурированные подсказки и удалённый экран

Подсказка (`Hint`) — единица вывода: вопрос (когда распознан), мгновенный короткий ответ, статус потока и необязательное раскрытие (длинный ответ по запросу). Лента подсказок — единый источник для локального оверлея и для удалённого экрана; история сессии и прошлых сессий доступна там же.

Удалённый экран — встроенный в приложение сервер в локальной сети: HTTP отдаёт одностраничный веб-интерфейс, WebSocket транслирует события ленты и принимает команды («Ответить сейчас», «Подробнее», «Сбросить контекст», смена режима). Доступ только по токену сопряжения, по умолчанию выключен. Интерфейс сначала рассчитан на большой экран Mac (две колонки: лента и раскрытие), на телефоне те же блоки в столбик.

## Что не меняется

- Три взаимоисключающих режима; `passive` не захватывает, не распознаёт, не вызывает API провайдеров и не сохраняет контент.
- Критический путь ответа без локального STT для OpenAI Realtime (ADR 0002); раздельные пайплайны провайдеров (ADR 0004).
- Ключи только в Keychain; содержимое разговоров не попадает в логи и диагностику без явного opt-in.
- Данные одного провайдера не уходят другому: раскрытие подсказки использует провайдера активной сессии.

## Критерии готовности MVP

- Можно создать область «X», положить в `Knowledge/X/` три markdown-файла и увидеть их в подсказках следующей сессии без действий в UI, кроме проверки.
- Несколько активных областей дают один связный ответ; неактивная область не попадает в инструкции (проверяется тестом на текст инструкций).
- Подсказка появляется на втором устройстве не позже, чем в локальном оверлее, с точностью до сетевой задержки; «Подробнее» на втором устройстве даёт раскрытие тем же провайдером.
- Без токена WebSocket отклоняется; при выключенном удалённом экране порты не слушаются; в `passive` новых подсказок не возникает, а авторизованное устройство видит состояние и историю.
- `make verify-fast` проходит; реальные API и аудио проверяются вручную по протоколу README.
